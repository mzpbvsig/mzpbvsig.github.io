领域知识与业务，才是真正的关键

你已经学完了所有机制（流程 / spec / 文件夹 / 复查）。一个对的结论浮现了：这些机制是通用管道，谁都能学会、很快趋同；真正拉开产出差距的，是你往管道里灌的 领域知识与业务理解。本文用证据印证它，并把你学过的每个机制重新解释成"装领域知识的容器"。

机制（流程·spec·文件夹·复查）= 管道，会贬值、会趋同
领域知识 + 业务理解 = 你灌进管道的水，才是差异与价值所在

证据：业界已得出同样结论

SDD 研究 "specifications should use domain-oriented ubiquitous language to describe business intent rather than specific tech-bound implementations."
—— spec 要用「领域通用语言」表达业务意图，而不是绑死技术实现。
Augment "creating specifications accurate enough for AI generation requires reverse-engineering years of implicit business logic."
—— 让 spec 精确到能给 AI 生成，难点是把多年「隐性业务逻辑」逆向出来。
Anthropic 官方 CLAUDE.md "gives Claude persistent context it can't infer from code alone."
—— CLAUDE.md 给的是代码里推不出来的上下文（= 领域/业务知识）。
Anthropic 官方 Skills "extend Claude's knowledge with information specific to your project, team, or domain."
—— skills 就是往 Claude 里加你项目/团队/领域专属知识。

→ 三方独立说同一件事：瓶颈不在工具，在"把隐性领域/业务知识显性化"。

为什么工具不是关键

  • 机制会趋同：plan mode、4 阶段、spec 文件夹、对抗式复查——都是公开文档，人人能照抄，不构成壁垒。
  • 最大失败模式是"解决错问题"：官方原话 "code that solves the wrong problem"。流程再标准，需求理解错了全白做——而需求理解 = 业务/领域。
  • AI 把"写代码"变便宜了：当生成代码近乎免费，价值就上移到"该写什么、为什么、边界在哪"——这恰恰是领域知识回答的。
  • 幻觉的根因是缺上下文：Claude 不是不会写，是不知道你这行的规则。补领域知识 > 调 prompt 技巧。

关键转念：你学的每个机制，都是"领域知识的容器"

把前面学的东西重看一遍——它们的价值不在结构本身，在里面装的领域/业务内容：

机制（容器）它真正承载的领域/业务知识
CLAUDE.md本项目的约定、命令、踩坑点、架构决策——"代码里推不出来"的隐性规则
steering/product.md业务方向：为谁做、解决什么、成功标准
steering/tech.md本领域的技术栈与取舍
steering/structure.md本项目代码组织的领域约定
constitution.md项目宪法：不可逾越的业务/合规原则
spec.md / requirements.md业务意图：用户故事、验收标准、边界、不做什么
.claude/skills/可复用的领域专长（API 约定、合规规则、行业算法）
所以：你不是"学会了 spec-kit / Pimzino"，你是学会了往哪些槽位灌业务知识。槽位是死的，灌得好不好取决于你对业务有多懂。

那该把精力放哪（务实落地）

  • ① 把隐性业务逻辑写下来：那些"老员工才懂"的规则、例外、为什么这样设计——逆向出来写进 steering/ 与 spec.md。这是最高杠杆的活。
  • ② 用领域通用语言：spec 写"业务发生了什么"，别写"调哪个函数"。让业务方能看懂、能纠错。
  • ③ 把验收标准写成业务可验证的："登录失败 3 次锁定 15 分钟"这种，才挡得住 AI 想当然。
  • ④ 复用沉淀成 skill：反复用到的领域规则 → 抽成 .claude/skills/，按需加载、不占上下文（progressive disclosure）。
  • ⑤ 你做"领域翻译官 + 验收官"：AI 负责实现，你负责"对不对、合不合业务"——这是 AI 替不掉的位置。
一句话提醒：流程和工具学到头，边际收益递减；对业务/领域的理解，是没有上限、且 AI 越强越值钱的资产。把时间从"调工具"挪到"把业务知识显性化"。
结论：机制是通用管道、会趋同；领域知识与业务理解是你灌进去的水，才是差异化价值。你学过的 CLAUDE.md / steering / spec / skills 全是"装领域知识的容器"——价值取决于你往里装什么。把精力从调工具，转向"把隐性业务逻辑显性化、写成 AI 能执行的规格"。
