Task / Phase / Sprint 三者关系

这三个词分属两个不同体系，而且 "Phase" 在两边层级正好相反，"Sprint" 在真正的 Claude Code spec 工具里根本不出现。本文把两套层级、冲突点、以及"想合成一套时的务实映射"讲清，并标注哪些是真实证据、哪些是构造建议。

一句话先记住：Agile 里 Phase > Sprint > Task；spec-kit 里 Feature > User Story > Phase > Task（无 Sprint）。同一个词 "Phase"，一个在 Sprint 之上、一个在 User Story 之下——这是最大歧义来源。

体系 A · 真实证据通用 Agile / Scrum

Project 项目 └─ Phase / Iteration 阶段 / 迭代 ← 这里的 Phase = 高层"生命周期阶段" └─ Sprint 冲刺（1–4 周时间盒） └─ Task 任务（从 backlog 拉进 sprint backlog） └─ Subtask 子任务
  • 层级：Phase > Sprint > Task。
  • Sprint：一个固定时长的时间盒；sprint 里"装"从产品 backlog 挑出的任务/故事。
  • Phase：项目级的大阶段（在 sprint 之上）。
证据：Tempo / Flowlu Agile 规划 ↗

体系 B · 逐字证据Claude Code 的 spec 工具（spec-kit / Pimzino）

Feature 功能 └─ User Story 用户故事（P1 / P2… 优先级） └─ Phase 阶段 ← 这里的 Phase = 一个 tasks.md 内部的分组 │ Phase 1 Setup · Phase 2 Foundational · Phase 3+ 每故事一段 └─ Task 任务（T001 · [P]并行 · [US1]归属 · 依赖 · [ ]→[x]） └─ （任务里的 bullet 步骤 / File / Requirements）
  • 层级：Feature > User Story > Phase > Task。没有 Sprint。
  • Phase：不是时间盒，只是某个功能的任务清单里的逻辑分段（搭建→地基→各故事）。
  • 来源：这套层级来自前面逐字拉取的 spec-kit / Pimzino 真实模板。
证据：spec-kit tasks-template.md ↗ · 详见同目录 task-phase清单-真实用法.html

关键冲突（最容易踩的坑）

词Agile 里的层级spec-kit 里的层级
Phase在 Sprint 之上（项目级阶段）在 User Story 之下（tasks.md 内部分组）
Sprint存在，是时间盒不存在
Tasksprint 里的活儿phase 里的原子任务（T001…）
同一个 "Phase"，两边指的不是一个层级——讨论时一定要先说清"你说的 phase 是哪套"。

体系 C · 构造建议（非官方）想把三者合成一套时的务实映射

Sprint 冲刺（你这一轮要交付的范围 / 时间盒） └─ Feature / User Story 这轮挑的功能 / 故事 └─ Phase 阶段（spec-kit 的 Setup → Foundational → 每故事） └─ Task 原子任务（T001，[ ] → [x]） └─ Subtask / steps 子步骤
  • 含义：Sprint 决定"这轮做哪些故事"（范围+时间），Phase / Task 决定"每个故事怎么一步步落地"（执行）。
  • 用法：用 Sprint 做"挑活儿 + 收口节奏"；进到每个故事，就用 spec 工具的 tasks.md（Phase + Task + 勾选 + 验证）来驱动 Claude Code 逐条实现。
诚实标注：体系 C 是把 Agile 的 Sprint 叠在 spec 工具之上的务实组合，不是哪个工具的官方定义；spec-kit / Pimzino 本身不含 Sprint 概念。按需采用。
怎么对齐需求：如果你只在 Claude Code 里做一个功能 → 用体系 B（Feature→Story→Phase→Task）就够，别引入 Sprint 徒增混乱。若你在团队 Agile 节奏里 → 用体系 C：Sprint 管范围与节奏，每个故事落到 tasks.md 的 Phase/Task 去执行。
