English（原文）
## Format: `[ID] [P?] [Story] Description`
- **[P]**: Can run in parallel (different files, no deps)
- **[Story]**: Which user story (e.g., US1, US2, US3)
- Include exact file paths in descriptions

## Phase 1: Setup (Shared Infrastructure)
**Purpose**: Project initialization and basic structure
- [ ] T001 Create project structure per impl plan
- [ ] T002 Initialize [language] project with [framework]
- [ ] T003 [P] Configure linting and formatting tools

## Phase 2: Foundational (Blocking Prerequisites)
**Purpose**: Core infra that MUST be complete before
ANY user story
**⚠️ CRITICAL**: No user story work can begin until
this phase is complete
- [ ] T004 Setup database schema and migrations
- [ ] T005 [P] Implement auth/authorization framework
- [ ] T007 Create base models all stories depend on
**Checkpoint**: Foundation ready - user story impl
can now begin in parallel

## Phase 3: User Story 1 - [Title] (Priority: P1) 🎯 MVP
**Goal**: [What this story delivers]
**Independent Test**: [How to verify it alone]
### Tests for US1 (OPTIONAL - only if requested) ⚠️
> **NOTE: Write tests FIRST, ensure they FAIL
> before implementation**
- [ ] T010 [P] [US1] Contract test for [endpoint] in
      tests/contract/test_[name].py
### Implementation for User Story 1
- [ ] T012 [P] [US1] Create [Entity1] model in
      src/models/[entity1].py
- [ ] T014 [US1] Implement [Service] in
      src/services/[service].py (depends on T012, T013)
**Checkpoint**: US1 fully functional, testable alone

## 格式：`[ID] [P?] [Story] 描述`

**目的**：在任何用户故事开工前必须完成的

> 再去实现**

形态 2 · Pimzino/claude-code-spec-workflow（专为 Claude Code）

社区逐字.claude/templates/tasks-template.md（节选）Pimzino ↗
English（原文）
## Atomic Task Requirements
- **File Scope**: Touches 1-3 related files maximum
- **Time Boxing**: Completable in 15-30 minutes
- **Single Purpose**: One testable outcome per task
- **Specific Files**: Must specify exact files

## Good vs Bad Task Examples
❌ "Implement authentication system"
   (affects many files, multiple purposes)
✅ "Create User model in models/user.py with
   email/password fields"

## Tasks
- [ ] 2. Create base model class in
      src/models/FeatureModel.ts
  - File: src/models/FeatureModel.ts
  - Implement base model extending BaseModel class
  - Purpose: Provide data layer foundation
  - _Leverage: src/models/BaseModel.ts,
    src/utils/validation.ts_
  - _Requirements: 2.1_
- [ ] 3. Add specific model methods to FeatureModel.ts
  - File: src/models/FeatureModel.ts (continue task 2)
  - Implement create, update, delete methods
  - _Requirements: 2.2, 2.3_
中文对照
## 原子任务要求
- **文件范围**：最多碰 1–3 个相关文件
- **时间盒**：15–30 分钟内能完成
- **单一目的**：每个任务一个可测产出
- **明确文件**：必须写明确切文件

## 好 vs 坏 任务示例
❌ "实现认证系统"
   （牵动很多文件、目的不单一）
✅ "在 models/user.py 创建带 邮箱/密码
   字段的 User 模型"

## 任务
- [ ] 2. 在 src/models/FeatureModel.ts
      创建基础模型类
  - 文件：src/models/FeatureModel.ts
  - 实现继承 BaseModel 的基础模型
  - 目的：提供数据层地基
  - _复用：src/models/BaseModel.ts,
    src/utils/validation.ts_
  - _需求：2.1_
- [ ] 3. 给 FeatureModel.ts 增加具体模型方法
  - 文件：src/models/FeatureModel.ts（接续任务2）
  - 实现 create、update、delete 方法
  - _需求：2.2, 2.3_
字段含义（中）
File:本任务要创建/修改的确切文件
Purpose:这步要达成的单一目的
_Leverage: …_可复用的现有代码，别重造轮子
_Requirements: X.Y_回链 requirements 文档的需求编号，保证可追溯

清单怎么被驱动（对照）

社区逐字四阶段 + 每任务循环
English（原文）
Requirements → Design → Tasks → Implementation
(bug fix: Report → Analyze → Fix → Verify)

For each task in tasks.md:
  Implement → Review → log-implementation
            → Mark completed ( [x] )

Approval gate between each phase.
中文对照
需求 → 设计 → 任务 → 实现
（修 bug：报告 → 分析 → 修复 → 验证）

对 tasks.md 里的每条任务：
  实现 → 审查 → 记录实现
       → 标记完成（ [x] ）

每个阶段之间都有审批闸门。
怎么用：大功能在 spec 接力的"③ tasks"环节产出这种 tasks.md（Phase + 确切文件 + 依赖 + Requirements 回链 + 勾选框）；实现时逐条做、做完打 [x]、每条跑验证，阶段闸门处停下等确认。长任务因此可中断可续接、每步可验收。

诚实边界：① 这两套是社区/工具包约定（spec-kit 为 GitHub 官方工具包但 agent 无关；Pimzino 为社区），非 Claude Code 内置强制格式。② Claude Code 另有自带任务追踪（~/.claude/tasks/、TodoWrite，支持依赖/阻塞/跨会话），与本文 markdown 清单是两套，可配合勿混。
