Transformer 执行流程：从分词到 Top-k

把一次「文本 → 下一个 token」的前向推理，按阶段拆开，逐段给出算法步骤与时间复杂度。 符号约定见下；每条复杂度结论尽量附可溯源链接与英文原文。分析以推理（inference）视角为主，分词段会额外点出训练与编码的区别。

符号约定

d_ffFFN 中间维度（≈4d）

三类标签

官方逐字 —— 来自论文/权威文档的原文结论（附英文 + 链接）。

两个真正的瓶颈：① 注意力的 O(n²·d)（序列一长就平方爆炸）；② LM head 的 O(d·V)（词表一大就贵）。下面逐段展开。

② 分词：BPE 编码

① Tokenization（BPE） 编码 O(n·l²) · 训练 O(N·M)

步骤
  • 预切分：用正则把文本切成「词」（GPT 用字节级，按空格/标点边界）。
  • 初始符号化：每个词拆成单字节/字符序列。
  • 贪心合并：在已学好的合并表里，反复挑出「优先级最高（rank 最小）的相邻对」合并，直到没有可合并的对。
复杂度推导
  • 单个词长 l：每轮扫一遍相邻对找最优是 O(l)，最多合并 l-1 次 → 朴素 O(l²)。用优先队列按 rank 选可降到 O(l log l)。
  • 整条序列 n 个词：O(n·l²)。由于 l 很小（一般 < 16），分词相对后面的矩阵运算几乎可忽略。
  • 实践补充 注意 BPE 合并不跨词边界——这是预切分决定的，不是合并算法本身。
官方逐字 训练阶段的复杂度：朴素实现每次合并要扫描整个语料找最频繁对，整体约为 O(N·M)（N=语料 token 数，M=合并次数）；用优先队列/增量计数可显著降低。 "The naive BPE training algorithm is generally O(n·m) per merge iteration… optimized implementations using priority queues or incremental counting can significantly reduce this." jytan.net · Building a Fast BPE Tokenizer ↗ · HF Course · BPE ↗

② 词嵌入查表（Embedding） O(n) · 表占 O(V·d)

步骤
  • 每个 token id 去一个 [V × d] 的查找表里取对应行向量（gather 操作）。
  • n 个 token → 拼成 [n × d] 的输入矩阵。
复杂度
  • 查表本身是 O(1)/token（数组下标取行），整条 O(n)。
  • 写出 n×d 个浮点的结果数据量是 O(n·d)，但这是数据搬运而非算力。
  • 看场景可省 很多模型把输入嵌入表和 LM head 共享权重（weight tying），省掉一份最大的权重矩阵。

③ 位置编码（Positional Encoding） O(n·d)

步骤与复杂度
  • 正弦/学习式：生成或查到一个 [n×d] 的位置向量，逐元素加到嵌入上 → O(n·d)。
  • RoPE（旋转位置编码）：对 Q、K 的每对维度做旋转，按位置乘上角度 → 仍是 O(n·d)，是当代主流（Llama / Qwen 系）。
  • 相比后续注意力，这一步开销可忽略。

③ 注意力：整个流程的「平方瓶颈」

④ 多头自注意力（核心） O(n²·d + n·d²)

一个注意力层 = QKV 投影 + 缩放点积注意力 + 输出投影。逐子步拆复杂度（以单层、全序列 prefill 为例）：

4-1. Q / K / V 投影
  • 三个权重矩阵各 [d×d]，输入 X[n×d] → Q,K,V 各 [n×d]。
  • 每个是 (n×d)·(d×d) = O(n·d²)，三个 → 仍是 O(n·d²)（常数 3 不进量级）。
  • 多头等价：h 个头各 n×d_k，h·n·d·d_k = n·d²，总量级不变。
4-2. 注意力打分 QKᵀ —— 平方项
  • S = Q·Kᵀ：(n×d)·(d×n) → [n×n] 打分矩阵，O(n²·d)。
  • 这是「序列一长就爆炸」的根源：长度翻倍，算力/显存×4。
4-3. 缩放 + 掩码 + softmax
  • 除以 √d_k：O(n²)。因果掩码：O(n²)。
  • softmax 对每行归一化：n 行 × 每行 n 元素 = O(n²·h)（被 matmul 的 O(n²·d) 吃掉，不单独成瓶颈）。
4-4. Attn·V + 输出投影
  • O = softmax(S)·V：(n×n)·(n×d) → O(n²·d)。
  • 输出投影 W_O：(n×d)·(d×d) → O(n·d²)。
单层注意力合计：O(n²·d + n·d²)
前者是「长序列」杀手，后者是「大模型维度」杀手。当 n≫d 时 O(n²·d) 主导；当模型很大、序列不长时 O(n·d²) 主导。
官方逐字 自注意力时间复杂度必然是输入长度的二次方——除非强指数时间假设（SETH）不成立，否则无法绕开。 "We prove that the time complexity of self-attention is necessarily quadratic in the input length, unless the Strong Exponential Time Hypothesis (SETH) is false." arXiv 2209.04881 · On The Computational Complexity of Self-Attention ↗
官方逐字 完整一层（含 V 投影）总复杂度记为 O(n²·d + n·d²)。 "the total complexity as O(n²·d + n·d²), accounting for both the attention score computation (n²·d) and the value-projection step (n·d²)." StackOverflow · Self-Attention Complexity ↗
实践补充 训练 vs 推理的关键差异
训练 / prefill
一次性吃下整条 n 个 token，注意力是完整的 n×n 矩阵 → 老老实实付 O(n²·d)。
生成解码（decode，逐 token）
每步新 token 只需和已生成的做注意力；用 KV cache 缓存历史 K/V 后，每步注意力退化为 O(n·d)（1×n）而非 O(n²·d)。

这也是为什么「prefill 阶段吃算力（compute-bound），decode 阶段吃显存带宽（memory-bound）」。

看场景可省 降低平方项的工程手段
  • FlashAttention：不降理论 O(n²·d)，但通过分块（tiling）把 n×n 矩阵不落盘，把 HBM 读写从 O(n²) 降到 O(n²d/M)，实际快 2~4×。
  • 稀疏/线性注意力（Sparse / Linear Attention）：把理论降到近 O(n·d)，代价是表达力下降。

⑤ 前馈网络 FFN O(n·d·d_ff) ≈ O(n·d²)

步骤与复杂度
  • 两个线性层夹一个激活：(n×d)·(d×d_ff) + (n×d_ff)·(d_ff×d)。
  • 通常 d_ff = 4d → 总量 O(n·d·d_ff) ≈ O(n·d²)（4 倍常数吸收进量级）。
  • FFN 是逐 token 独立的（不同位置之间不交互），所以不含 n² 项——这是它和注意力的本质区别。
  • 实践补充 MoE（如 DeepSeek/Mixtral）把 FFN 拆成多个专家、每 token 只激活少数，把有效算力降到 O(n·d·d_ff / num_experts_active)，是降 O(n·d²) 的主流做法。

⑥ 层叠加 ×L O(L·(n²·d + n·d²))

合计
  • 每层 = 注意力 + FFN + 残差连接 + LayerNorm/RMSNorm。
  • 残差是逐元素加 O(n·d)；归一化 O(n·d)，相对可忽略。
  • L 层 → O(L·n²·d + L·n·d²)。这就是「Transformer 主体」的总算力。

④ 收尾：把隐藏向量变回「词表上的分数」

⑦ LM head / Unembedding（logits） O(d·V)/步 · 全序列 O(n·d·V)

步骤与复杂度
  • 最后一层归一化后，用 [d×V] 的 unembedding 矩阵投影：(n×d)·(d×V) → 每个位置得到 V 维 logits。
  • 全序列 O(n·d·V)。实践补充 生成时只需末位 token 的 logits → 每步 O(d·V)。
  • V 通常 3 万~20 万+，所以这个矩阵常常是模型里最大的单一权重矩阵，是「大词表瓶颈」。
官方逐字 unembedding 矩阵形状为 [d × |V|]，词表每个 token 对应一列。 "the unembedding matrix has shape [d × |V|], with one column per vocabulary token." Stanford CS124 · LLM 讲义 ↗
官方逐字 投影 (n×d)·(d×V) 复杂度 O(n·d·V)，因词表巨大而被公认是输出端瓶颈；自适应 softmax、绑定嵌入、层次 softmax、低秩投影等都是为压它而生。 "Since modern LLMs have vocabularies of 30K–200K+ tokens, this final projection is disproportionately expensive — often the single largest weight matrix." llm.modular.com · LM head ↗

⑤ 采样：从 V 维 logits 里抽出下一个 token

⑧ Top-k 采样 O(V log k) 或 O(V)

步骤
  • ① 拿到末位 token 的 V 维 logits（来自上一步）。
  • ②（可选）温度缩放：逐元素 logits/τ，O(V)。看场景可省
  • ③ 选 top-k：从 V 个分数里挑出最大的 k 个。
  • ④ 对这 k 个做 softmax 重归一化 O(k)。
  • ⑤ 按概率抽样 O(k)（或别名法 O(1)）。
第③步「选 top-k」的三种实现
方法时间说明
全排序后取前 kO(V log V)最直观但最贵
大小为 k 的最小堆O(V log k)流式扫描，k≪V 时常用
部分选择 nth_elementO(V) 均摊 + O(k log k)最省，生产推理常用

所以 top-k 整段通常记作 O(V log k)（堆式），工程实现常到 O(V)。相对前面的 O(d·V) 投影，采样本身是小头——真正贵的是「把 V 维 logits 算出来」那一步。

官方逐字 一次完整采样的复杂度可写成 O(T·(inference + K·log(V)))（T=生成 token 数，K=采样数，V=词表）。 "an explicit complexity formula: O(T × (inference + K·log(V)))" arXiv 2402.18734 · Priority Sampling ↗
看场景可省 三种采样策略对比
策略做法复杂度
贪心 / argmax直接取最大 logitO(V)
top-k固定保留 k 个最大O(V log k)
top-p（核采样）保留累计概率达 p 的最小集合O(V log V) 朴素 / O(V + k log k) 配合预筛

三者都建立在「先有 V 维 logits」之上，所以瓶颈不在选法，而在算 logits（即上一节的 O(d·V)）。

⑥ 闭环：生成一个 token，再喂回去

采样出的新 token id → 追加到序列末尾 → 作为下一步输入。自回归生成 T 个 token 时：

  • 无 KV cache：每步都重算全部 L 层对全长序列的注意力 → 每步 O(L·(n²·d + n·d²))，总共 O(T·L·n²·d) 级别。
  • 有 KV cache：每步只算新 token 的 Q 对历史 K/V 的注意力（1×n），主体算力降到每步约 O(L·(n·d + n·d²) + d·V)，T 步累计约 O(T·L·(n·d² + n·d) + T·d·V)。这是真实推理引擎（vLLM / SGLang 等）默认做的优化。
一句话总结全流程算力结构：
主体是 L·(n²·d + n·d²)（注意力平方项 + FFN/投影线性项），收尾是 d·V（大词表投影），采样 V log k。 两个瓶颈：长上下文砸 O(n²·d)，大词表砸 O(d·V)。
