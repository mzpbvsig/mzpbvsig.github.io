官方解读 · 动态工作流 Dynamic Workflows

原文：A harness for every task: dynamic workflows in Claude Code · 2026-06-02 · Claude 官方博客

这篇是我们刚聊的 fork / subagent 的"放大版"：Claude Code 现在能自己写一个多 agent 编排（dynamic workflow），针对具体任务定制，去啃复杂、长时、需要对抗校验的活。本文逐节拆它是什么、怎么跑、解决什么、什么时候别用。

动态工作流 = Claude 临时写一段 JavaScript，
在后台编排几十~上百个 subagent（各自独立上下文）去协作完成一个大任务

核心定义

词含义
Agentic harness
(执行骨架)		协调 agent 行为的底层执行框架
Dynamic workflow
(动态工作流)		一段 JavaScript 编排文件，负责 spawn 和管理一群 subagent（各自隔离上下文）
Subagentworkflow 里被生出来的单个 Claude 实例，各自有聚焦目标

技术能力：workflow 跑的是 JS（含 spawn subagent 的特殊函数 + JSON/Math/Array 等标准库），可指定模型、worktree 隔离、被打断后可续跑(resumable)。

和默认模式的区别：平时 Claude Code 是"单一骨架"一条道跑；动态工作流是让它按任务自己造一个多 agent 骨架——从"一个 Claude"变成"一个被编排的 Claude 舰队"。

为什么需要它：治三种"失败模式"

  • ① Agentic laziness（偷懒早收工）：没真做完就宣告完成 → 用 loop-until-done 等模式逼它干到底。
  • ② Self-preferential bias（自我偏袒）：不愿质疑自己的产出 → 用对抗校验，让另一个 agent 专门挑错（呼应官方"写代码的不能自己验自己"）。
  • ③ Goal drift（目标漂移）：跨多个上下文窗口后目标走样 → 用结构化编排把目标钉住。
串起前面学的：这三个正是单会话/单 agent 的固有弱点。动态工作流用"多 agent + 对抗 + 结构"来系统性地补——是"收口/验证关"思想的工程化放大。

6 个常用编排模式

classify-and-act # 先分类，再按类处理 fan-out-and-synthesize # 散开并行 → 汇总综合 adversarial verification # 对抗校验：专门派 agent 挑错 generate-and-filter # 大量生成 → 过滤留好的 tournament selection # 锦标赛：多方案两两比，选最优 loop-until-done # 循环到真完成为止（治偷懒）

→ 这些是可组合的积木，按任务拼出合适的"骨架"。

标杆案例：Bun 从 Zig 移植到 Rust

原文 "Bun was rewritten from Zig to Rust using workflows," breaking tasks into discrete fix operations across subagents with adversarial review stages.
把大任务拆成一个个离散修复操作，分给众多 subagent，并加对抗评审环节。

规模：75 万行代码，11 天合并完成——传统专职团队估计要 6–12 个月。

什么时候别用（官方明确划线）

原文 Workflows "often use more tokens and are best suited for complex, high value tasks."
工作流更费 token，只适合复杂、高价值的任务。
别用的情况：普通编码任务不需要这套开销——杀鸡别用牛刀。这跟我们聊 fork/subagent 时的结论一致：能用简单手段达到的，就别上重型编排。

实用建议

原文 "Pair triage workflows with /loop to have Claude do this continuously."
把"分诊类"工作流配上 /loop，让 Claude 持续处理积压（backlog 自动消化）。

它在你已学的版图里的位置

层级是什么何时
单 prompt口语随手说小修改
subagent一个隔离上下文的助手调查/评审，不需你的历史
fork / branch带你上下文的后台/副本会话上下文重、想异步或自己开

一句话定位：它是这条"由轻到重"光谱的最重端——只在任务大到单 agent 扛不住、且值得多花 token 时才出手。
结论：动态工作流 = Claude 按任务自己写 JS 编排几十上百个 subagent，用对抗校验/循环到底/锦标赛等模式，治"偷懒、自我偏袒、目标漂移"三大单 agent 弱点；标杆是 Bun 11 天移植 75 万行。代价是更费 token，只对复杂高价值任务划算，普通编码别上。
