实践补充

Evidence Review · Agent Loops

你说的不是 Graph Agent，
更像是 Ralph Agent

从 2025 年的 Ralph Wiggum Bash 循环，到 OpenAI 的真实工程案例、Anthropic 的长时 harness，再到 Boris Cherny 的“我的工作是写 loops”：他们讲的是同一条技术演化，但并没有宣布“prompt 已死”或“无人软件公司已经成熟”。

核验日期：2026-08-02 · 优先采用原作者文章、公司工程博客、原始演讲视频；二手报道仅用于定位原视频与交叉核验。

实践补充 · 结论 真实共识：人的杠杆点从“每轮亲自提示”上移到“设计可持续闭环”。

目标、状态、工具、验证、停止条件和恢复路径，比某一句神奇 prompt 更重要。模型仍在写代码；人开始编排“谁发现工作、谁执行、谁验收、何时停止”。

溯源纠正 “Google 也正式表态”证据不足。

可查到的是 Addy Osmani 的个人文章。页面明确声明其观点不代表 Google；因此只能记为 Google 背景专家的个人判断，不能记为 Google 官方路线。

先把四个词分清

网络传播把 Ralph、harness、loop engineering 和 graph agent 混成了一个词，实际上它们处在不同层级。

Graph Agent把工作流显式写成有向图：节点、边、分支、状态转移。它强调结构可视化与确定性路由。
Ralph Loop反复启动编码 Agent；每轮从磁盘读取规格和进度，做一个增量，再把状态写回磁盘。
Harness Engineering设计单次/多次 Agent 运行所依赖的工具、文档、沙箱、上下文策略、测试与恢复机制。
Loop Engineering再上移一层：触发、发现任务、分派、隔离、验收、记忆、预算、停止与升级都由系统循环管理。
一句话：Graph 描述“工作流长什么样”；Ralph 是最小可用循环；harness 是 Agent 的工作环境；loop engineering 是让整套工作自己持续运转的控制系统。

证据时间线：这股风到底怎么起来的

2025-07-14 · Geoffrey Huntley

Ralph Wiggum：最初只是一个 Bash 循环

原始做法极简：重复调用 Claude Code；每次只做一个任务；计划、规格和进度放在文件里；通过测试与构建提供 backpressure。重点不是“无限跑”，而是新上下文 + 外部状态 + 快速反馈。

实践原文“Ralph is a technique. In its purest form, Ralph is a Bash loop.”Ralph 是一种技巧；最纯粹的形态就是一个 Bash 循环。— Geoffrey Huntley，Ralph Wiggum as a “software engineer”
2026-02-11 · OpenAI 官方工程博客

OpenAI：把 Ralph 变成真实软件工厂的一部分

OpenAI 披露一个“人工不直接写代码”的内部产品实验：Codex 生成约百万行代码，三名工程师在五个月内合并约 1,500 个 PR。流程中 Agent 会自审、拉其他 Agent 复审、处理反馈，循环到 reviewers 满意；文章明确称这“实际上就是 Ralph Wiggum Loop”。

官方逐字“Humans steer. Agents execute.”人类掌舵，Agent 执行。— OpenAI，Harness engineering: leveraging Codex in an agent-first world
2026-03-24 · Anthropic 官方工程博客

Anthropic：单纯循环还不够，要分离规划、生成与评估

Anthropic 认为复杂任务里会出现上下文失去连贯、过早结束和“自己夸自己”的自评偏差，于是使用 planner–generator–evaluator 三 Agent 结构、结构化交接和可测试 sprint contract。它把 Ralph 视作社区收敛出的起点，不是终点。

官方逐字“Every component in a harness encodes an assumption about what the model can't do on its own.”Harness 的每个组件，都编码了一个“模型无法独立完成什么”的假设。— Anthropic，Harness design for long-running application development
2026-06-02 · Boris Cherny / WorkOS 原始访谈

Claude Code 创建者：新的抽象层是“写 loop”

Boris 描述的是一条连续演进：手写代码 → 多个 Agent 并行写代码 → 由循环持续给 Agent 生成任务。他紧接着说这是未来几个月到年底可能发生的转变，因此更准确地说，这是前沿工作方式和预测，不是“所有人今天都不该写 prompt”的命令。

本人逐字“I don't prompt Claude anymore. I have loops that are running… My job is to write loops.”我不再亲自提示 Claude；我让 loops 运行……我的工作是写 loops。— Boris Cherny，Claude Code & the Future of Engineering
2026-06-07 · Addy Osmani 个人文章

“Loop Engineering”被整理成完整方法

Addy 把一个可运行 loop 拆成自动触发、worktree 隔离、skills、连接器、sub-agents，再加磁盘/任务系统中的持久状态。他还强调 maker/checker 分离、预算与人工升级。这篇文章传播很广，但底部明确注明“不代表 Google”。

个人观点“Loop engineering is replacing yourself as the person who prompts the agent. You design the system that does it instead.”循环工程，就是设计一个替你提示 Agent 的系统。— Addy Osmani，Loop Engineering；页面免责声明：不代表 Google

三方真正一致的，不是口号，而是六个工程部件

部件解决什么失败真实做法
明确目标Agent 做了很多事，却不知道何时算完成规格、验收条件、sprint contract；把“做得好”改成可观察结果。
外部状态上下文重启后失忆，长对话又会腐烂progress.md、计划文件、Git 历史、issue/Linear；对话可丢，状态不可丢。
可执行反馈模型只能凭感觉宣布“完成”测试、lint、类型检查、浏览器操作、日志、指标；失败直接回灌到下一轮。
执行与验收分离同一个 Agent 容易宽容地评价自己的产物maker/checker、generator/evaluator、独立 Agent review。
隔离与并行多个 Agent 同时改同一工作区会相互覆盖每任务一个 branch/worktree/sandbox；最后经 CI 和 review 汇合。
终止与升级无限烧 token、局部循环、错误自动放大时间/轮次/费用上限；无进展检测；遇到判断题、权限或高风险操作时交还人类。

宣传最容易省略的四个边界

反证 1

Ralph 原作者自己也没有说“到处都能无人值守”

Huntley 在原文结尾明确保留强边界：工程师仍需资深判断；当时的版本最适合 greenfield，甚至直说不会把 Ralph 用在既有代码库。后来产品与模型进步了，但这条警告说明最初案例不能被外推成普遍保证。

成本数据

更好的 loop 可能不是“免费增强”，而是昂贵的 test-time compute

Anthropic 的 retro game maker 对照中，单 Agent 运行约 20 分钟、成本 9 美元；完整 harness 约 6 小时、200 美元，超过 20 倍。输出质量明显更好，但这只是特定任务的个案，不是普适 ROI。

理解债务

吞吐提高后，人类注意力仍是瓶颈

Worktree 解决文件冲突，不能解决评审带宽、产品判断和系统理解。生成速度越快，越容易积累 comprehension debt：代码存在，但团队没人真正理解它。

官方限定

OpenAI 的百万行代码案例是“特殊环境中的内部实验”

文章自己说明，端到端自治高度依赖该仓库的结构、工具与长期投入，不应假定没有类似投资也能复现。它证明“这套方法能工作”，没有证明“随便套一层 loop 就能工作”。

所以，他们到底在说什么？

  1. 不是 Agent 更会聊天，而是 Agent 被放进了更好的控制系统。
  2. prompt 没消失。它从人每轮手写的主界面，变成 loop 内部可生成、可版本化、可替换的零件。
  3. 人的工作没有消失，而是上移。从写每行代码，转成定义目标、边界、评价函数、异常处理与最终责任。
  4. 真正的护城河是反馈资产。测试、规则、skills、项目知识和历史故障一旦被编码，后续每轮都能复用。
  5. 自治程度取决于可验证性。编译、测试、数值指标适合闭环；战略、审美、伦理与高风险决策仍需人。

证据评级

流传说法评级核验结果
OpenAI 在讲 Ralph/loop强证据OpenAI 官方工程博客直接点名 Ralph Wiggum Loop，并给出内部产品数据。
Claude Code 创建者说“我的工作是写 loops”强证据有 2026-06-02 原始演讲视频；完整上下文显示这是个人当前工作方式与近期预测。
Anthropic 工程体系认同长时 loop/harness强证据官方工程博客明确提 Ralph，并公开多 Agent harness、成本与失败模式。
Google 官方也在讲 Loop Engineering证据不足目前可确认的是 Addy Osmani 个人文章；其免责声明排除了官方背书解读。
Loop Engineering 意味着 prompt engineering 已死夸大loop 仍会生成与使用 prompt；Addy 也明确建议按任务平衡直接 prompting 与 loops。
