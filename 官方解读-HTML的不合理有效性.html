官方解读 · HTML 的不合理有效性

原文：Using Claude Code: The unreasonable effectiveness of HTML · 作者 Thariq Shihipar · 2026-05-20 · Claude 官方博客

这篇官方文章的核心：让 Claude Code 用 HTML 而不是 Markdown 输出，能拿到更高信息密度、更清晰的视觉组织、更易分享、可交互、更好地吸纳多源上下文。它正好印证了你"一律生成 HTML"的做法——你不是个人偏好，是踩在官方观点上。

官方结论：HTML > Markdown 作为 Claude Code 的产出格式
作者原话：用 HTML 是因为它让我"feel much more in the loop with Claude"

为什么用 HTML：官方给的 5 个理由

理由说什么
① 信息密度
Information Density		HTML 能塞表格、CSS、SVG 图、代码块、JS 交互、空间排布、内嵌图片——比 Markdown 承载多得多的数据
② 视觉清晰
Visual Clarity		大文档用 tab/插图/链接组织后更可读。作者原话："I tend to not actually read more than a 100-line Markdown file"——长 Markdown 根本不会看
③ 易分享
Shareability		HTML 能当链接发，无需特殊渲染；同事更愿意点开看规格/报告（Markdown 附件常被忽略）
④ 双向交互
Two-way		HTML 可放滑块/可调参数，用户改了设计能导回 Claude Code
⑤ 上下文吸纳
Data Ingestion		Claude Code 能从文件系统、MCP（Slack/Linear）、Chrome、git 历史取更广上下文——直接用 Claude.ai 拿不到这些

官方推荐的 5 类用法

场景HTML 怎么用
规格 / 计划做"探索文件"，多方案并排对比，标清各自取舍 ← 你的 spec 接力/关系图正是这类
代码评审渲染 diff + 行内批注 + 按严重度配色的发现
设计带可调参数的交互动画原型 + 一键复制
报告多源数据综合成可读文档 + SVG 图 ← 你这一整套研究文档
编辑做一次性 HTML 表单，导出按钮把数据/prompt 以 JSON 回传
对照你的文档集：你做的"规格并排对比 / 多源研究报告 / 配色标注证据"——三类全命中官方推荐用法。说明这条 CLAUDE.md 规则方向是对的。

最该记住的一句

作者逐字 "the real reason I use HTML instead of Markdown is that it helps me feel much more in the loop with Claude."
用 HTML 的真正理由：它让我对 Claude 在做什么更有掌控感、更跟得上。

→ 价值不只在"好看"，在人能更快看懂、更愿意读、从而更早发现问题——这跟官方反复强调的"紧反馈环 / 给自己能读的证据"是同一回事。HTML 是把"证据"做得让人愿意读的载体。

怎么开始（Getting started 要点）

  • 直接让 Claude Code "把结果做成单独的 HTML"，而不是默认 Markdown。
  • 大主题 → 让它用 tab / 折叠 / 链接 组织，别堆成长文。
  • 要对比 → 让它并排列方案 + 标取舍。
  • 要回传数据 → 让它在 HTML 里放导出按钮（输出 JSON 或 prompt）。
你已经在做的：暗色统一风格、左色条分段、配色标签、来源链接——等于把官方"信息密度 + 视觉清晰 + 易分享"三条工程化成了模板。
一句话：官方专门撰文说 HTML 作为 Claude Code 产出格式"不合理地有效"——信息密度高、可读、可分享、可交互、能吸更多上下文，核心好处是让人"more in the loop"。你的"一律生成 HTML"规则与官方立场一致。
