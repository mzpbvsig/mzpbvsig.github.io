Claude Code 真实用法证据库 · 按复杂度分层

目标：用真实证据说明不同复杂度的需求，应该怎么和 Claude Code 持续对话、用上哪些机制（plan mode / subagent / skills / MCP / 多会话 / 自验证闭环），用于对齐"完成需求"的方式。

诚实前提（重要）：公网上不存在一份"够长、逐行、又正确用满 skills/MCP/subagent 工具链"的真实连续 transcript（那种会被完整公开的，多是个人单会话蛮力 vibe coding，是反面教材）。
所以本库是真实片段拼成的证据库，不是一段连续对话：① 官方文档里的逐字示例 prompt；② Anthropic 官方团队报告里的真实工作流模式；③ 资深实践者公开写法。每条都标了来源与类型。Anthropic 那份团队报告原文是二进制 PDF，无法逐字解析，团队细节均来自官方博客+权威转述，统一标【团队报告·转述】。
标签： 官方逐字官方文档原样的示例 prompt 官方·转述官方文档要点（我归纳） 团队报告·转述Anthropic 团队用法（经转述） 实践者资深用户公开经验

T0 · 理解 / 探索（只读问答，不改代码）

复杂度：低。典型：上手新代码库、定位功能、问"这段为什么这么写"。核心机制：subagent 隔离调查，避免把一堆文件读进主上下文。
subagent 调查@文件引用CLAUDE.md
官方逐字新代码库速览：从宽到窄
give me an overview of this codebase
explain the main architecture patterns used here
what are the key data models?
how is authentication handled?
来源：官方 Common workflows ↗
官方逐字定位功能 + 追执行流
find the files that handle user authentication
how do these authentication files work together?
trace the login process from front-end to database
来源：官方 Common workflows ↗
官方逐字调查交给 subagent，主上下文只收结论
use a subagent to investigate how our auth system handles token refresh
官方原话：探索大代码库会把上下文塞满文件读取——让 subagent 在自己的上下文里读、只把摘要带回来。
来源：官方 Best practices ↗
团队报告·转述把"问代码库"当新人 onboarding
  • 基础设施团队：靠各目录的 CLAUDE.md 让 Claude 自动识别相关文件，帮新人快速上手数据管线。
  • 产品工程团队：把 Claude Code 当"任何编程任务的第一站(first stop)"，先做代码库分析再动手。
来源：How Anthropic teams use Claude Code ↗

T1 · 小改 / 明确的 bug（一句话能描述 diff → 直接做，不 plan）

复杂度：低。官方原话："If you could describe the diff in one sentence, skip the plan." 关键：prompt 里直接给文件、症状、可复现命令、什么算"修好"。
直接执行贴报错先写复现失败测试
官方逐字修 bug：贴错→给建议→落地
I'm seeing an error when I run npm test
suggest a few ways to fix the @ts-ignore in user.ts
update user.ts to add the null check you suggested
来源：官方 Common workflows ↗
官方逐字给症状 + 位置 + "修好"的样子（best practices 的 before→after）
❌ 模糊：fix the login bug
users report that login fails after session timeout. check the auth flow
in src/auth/, especially token refresh. write a failing test that
reproduces the issue, then fix it
来源：官方 Best practices ↗
官方逐字把验证塞进同一条 prompt（让它自己闭环）
❌ 模糊：the build is failing
the build fails with this error: [paste error]. fix it and verify the
build succeeds. address the root cause, don't suppress the error

T2 · 中等功能（多文件 / 方案不确定 → Explore→Plan→Implement→Commit）

复杂度：中。官方判据：不确定方案、改多文件、或对这块代码不熟时才值得 plan。核心机制：plan mode（Shift+Tab / --permission-mode plan） + 自验证。
plan mode测试闭环@引用/code-review subagent建 PR
官方逐字四阶段标准流程（OAuth 例）
① (plan) read /src/auth and understand how we handle sessions and login.
        also look at how we manage environment variables for secrets.
② (plan) I want to add Google OAuth. What files need to change?
        What's the session flow? Create a plan.
③ (run)  implement the OAuth flow from your plan. write tests for the
        callback handler, run the test suite and fix any failures.
④ (run)  commit with a descriptive message and open a PR
来源：官方 Best practices ↗
官方逐字渐进式重构（小步 + 每步验证）
find deprecated API usage in our codebase
suggest how to refactor utils.js to use modern JavaScript features
refactor utils.js to use ES2024 features while maintaining the same behavior
run tests for the refactored code
来源：官方 Common workflows ↗
官方逐字补测试（先找未覆盖→脚手架→边界用例→跑）
find functions in NotificationsService.swift that are not covered by tests
add tests for the notification service
add test cases for edge conditions in the notification service
run the new tests and fix any failures
来源：官方 Common workflows ↗
官方逐字收尾：新开上下文做对抗式审查
Use a subagent to review the rate limiter diff against PLAN.md. Check that
every requirement is implemented, the listed edge cases have tests, and
nothing outside the task's scope changed. Report gaps, not style preferences.
或直接用内置 /code-review skill：在新 subagent 里只看 diff 找 bug，结果回主会话。
来源：官方 Best practices ↗
团队报告·转述真实团队的中等任务模式
  • 安全工程：先让 Claude 出伪代码，再带着它走 TDD，保证可靠性与测试覆盖。
  • 推理团队：在不熟的语言（如 Rust）里让它生成覆盖边界的单测，自述 R&D 时间降 80%。
  • 数据基础设施：把出错截图喂进去，用 OCR 读图 → 诊断 Kubernetes IP 耗尽 → 给出修复命令（图像输入 + 诊断）。
来源：团队报告权威转述（Ernest Chiang）↗

T3 · 大功能（先 interview → 写 SPEC.md → 另开干净会话执行 → 自验证闭环）

复杂度：高。核心机制：让 Claude 反问你把需求挖透、落成自包含 spec；另开新会话带干净上下文执行；用自验证/自动循环收敛。这正是 Willison 那次没做、因而被反复自动压缩的地方。
AskUserQuestion 反问SPEC.md 交接fresh session自动测试循环auto-accept
官方逐字让 Claude 面试你，再写 SPEC.md
I want to build [brief description]. Interview me in detail using the
AskUserQuestion tool.

Ask about technical implementation, UI/UX, edge cases, concerns, and
tradeoffs. Don't ask obvious questions, dig into the hard parts I might
not have considered.

Keep interviewing until we've covered everything, then write a complete
spec to SPEC.md.
关键纪律：spec 写完另开会话执行；spec 要自包含——点名文件/接口、写明 out of scope、结尾给端到端验证步骤。
来源：官方 Best practices ↗
官方·转述用 /goal 把"验收条件"设成停机闸门
给 Claude 一个能跑出"通过/失败"的检查（测试套件、构建退出码、截图比对），用 /goal 设成会话级条件：每轮由独立评估器复检，不满足就继续干，直到成立。比"看起来做完了"可靠得多。
来源：官方 Best practices ↗
团队报告·转述真实团队的大功能模式
  • 产品设计：跑"自动循环"——Claude 写新功能代码→跑测试→持续迭代，从设计文件做到完整功能。
  • 产品开发：开 auto-accept 模式，让它自主写了某 Vim 模式约 70% 的代码。
  • 数据科学/ML：一发 prompt 在沙箱里从零写出整套 TypeScript 可视化，乃至 5000 行的 dashboard，从"一次性分析"升级成"长期可复用工具"。
来源：团队报告权威转述（Ernest Chiang）↗ · 另见 官方博客
实践者上下文管理：Document & Clear
大功能做到上下文将满时：让 Claude 把计划与进度 dump 进一个 .md → /clear → 新会话带着这份 md 继续。把"持续对话"做成"接力"，而不是无限堆积。
来源：Shrivu Shankar《How I Use Every Claude Code Feature》↗

T4 · 代码库级 / 批量 / 高保真（多会话并行 · fan-out · 写者-审者 · 子代理编排）

复杂度：很高。核心机制：横向扩展——worktree 并行会话、claude -p 扇出批处理、Writer/Reviewer 双会话、多 subagent 编排、定时/远程触发。
worktree 并行claude -p 扇出Writer/Reviewer多 subagentMCPRoutines 定时
官方逐字大迁移：列清单 → 脚本扇出 → 先试几个再全量
list all 2,000 Python files that need migrating
for file in $(cat files.txt); do
  claude -p "Migrate $file from React to Vue. Return OK or FAIL." \
    --allowedTools "Edit,Bash(git commit *)"
done
来源：官方 Best practices ↗
官方逐字Writer / Reviewer 双会话（新上下文审查无偏见）
会话A(Writer):  Implement a rate limiter for our API endpoints
会话B(Reviewer): Review the rate limiter implementation in
  @src/middleware/rateLimiter.ts. Look for edge cases, race conditions,
  and consistency with our existing middleware patterns.
会话A:           Here's the review feedback: [B output]. Address these issues.
来源：官方 Best practices ↗
官方逐字并行 worktree / 管道 / 定时
claude --worktree feature-auth          # 隔离的并行会话
git log --oneline -20 | claude -p "summarize these recent commits"
定时任务要把"成功长什么样、结果去哪"写死（它无法反问），例：Review open PRs labeled needs-review, leave inline comments, and post a summary in #eng-reviews Slack.
来源：官方 Common workflows ↗
团队报告·转述真实团队里唯一明确点名 subagent 的用法
增长营销：搭了一条 agentic 工作流，用两个专门的 sub-agent，把含上百条广告的 CSV 自动生成上百条新文案变体（外加 Figma 插件批量出图）。这是报告里少数逐字点名"sub-agents"的场景。
